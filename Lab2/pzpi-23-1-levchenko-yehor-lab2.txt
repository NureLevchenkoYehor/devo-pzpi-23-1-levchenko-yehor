     Метою роботи є отримання практичних навичок адміністрування Linux-систем, налаштування веб-сервера Apache, СУБД MySQL та інтерпретатора PHP (стек LAMP), а також автоматизації розгортання веб-орієнтованих систем на прикладі CMS OpenCart в операційній системі Debian.
     У межах роботи необхідно:
* підготувати систему та встановити необхідні залежності;
* встановити та налаштувати СУБД MySQL, створити користувача та базу даних для OpenCart;
* встановити та налаштувати HTTP-сервер Apache;
* встановити інтерпретатор PHP із менеджером процесів PHP-FPM та необхідними розширеннями й налаштувати взаємодію з Apache;
* завантажити та розгорнути CMS OpenCart, виконати її веб-інсталяцію;
* підготувати відеозапис демонстрації виконаної роботи, програмний код команд та оформити звіт відповідно до ДСТУ 3008:2015.
2.1 Вихідні умови
     Методичні вказівки допускають використання Debian 10 «або новішої» версії, а конкретні версії програмного забезпечення в них прив’язані до моменту написання. Тому роботу виконано на актуальних версіях, що призвело до таких відхилень від тексту методичних вказівок (обґрунтування наведено у розділі 4):
* замість віртуальної машини використано підсистему Linux для Windows (WSL), а замість Debian 10 – Debian 13 (trixie);
* замість PHP 7.3 використано PHP 8.4, яка доступна в репозиторії Debian 13;
* MySQL встановлено з офіційного APT-репозиторію MySQL (серія 9.7 LTS), оскільки Debian не постачає MySQL;
* замість OpenCart 3.0.3.8 використано OpenCart 4.1.0.4;
* PHP підключено до Apache через PHP-FPM (без libapache2-mod-php), а замість повного переліку пакетів встановлено лише ті, що потрібні для OpenCart;
* користувачу бази даних надано права лише на базу opencart, а не на всі бази (*.*).
3 ТЕОРЕТИЧНІ ВІДОМОСТІ
     LAMP – це класичний стек серверного веб-програмного забезпечення, який включає Linux (операційна система), Apache (веб-сервер HTTP), MySQL або MariaDB (система управління базами даних) та PHP (мова програмування для обробки динамічного контенту).
     OpenCart – популярна CMS (система керування вмістом) з відкритим початковим кодом, орієнтована на створення інтернет-магазинів.
     Веб-сервер Apache сам лише віддає файли, тому для обробки PHP-скриптів його необхідно поєднати з інтерпретатором PHP. Для цього існують такі підходи.
     CGI (Common Gateway Interface) – це специфікація інтерфейсу, що описує можливість веб-серверу виконувати зовнішні програми для обробки веб-запитів. Головна особливість полягає в тому, що зовнішня програма отримує дані запиту через змінні середовища та стандартний ввід. Після обробки зовнішня програма повертає результат виконання до серверу через стандартний вивід [1]. Специфікацію CGI описано в RFC 3875 [2].
     FastCGI – це специфікація бінарного інтерфейсу, що описує можливість веб-серверу взаємодіяти із зовнішніми програмами. Головна особливість полягає в тому, що запити веб-серверу передаються FastCGI-серверу (сервісу сервера), що підтримує з’єднання із зовнішньою програмою. Зовнішня програма отримує дані запиту через unix-сокет, TCP-з’єднання або іменований канал. Після обробки зовнішня програма повертає результат виконання до серверу, використовуючи той самий канал зв’язку. При цьому стан з’єднання не пов’язано із життєвим циклом FastCGI-сервера, дозволяючи йому обслуговувати декілька запитів за час свого життя [3].
     FPM (FastCGI Process Manager) – це реалізація менеджера процесів із використанням протоколу FastCGI.
     mod_php – це модуль Apache HTTP-сервера, який дозволяє інтерпретувати сирий php-файл та повертати його результат напряму, без передачі зовнішнім процесам. Цей підхід не є ані CGI, ані FastCGI, оскільки інтерпретатор працює всередині самого веб-сервера.

4.3 Встановлення репозиторію MySQL
     Debian відмовився від постачання MySQL, замінивши його на MariaDB, починаючи з Debian 9 [4]. Для MySQL існує окремий APT-репозиторій [5], який підключається пакетом mysql-apt-config. Його завантажено командою wget -c https://dev.mysql.com/get/mysql-apt-config_0.8.40-1_all.deb, де прапорець -c дозволяє докачати файл у разі обриву. Використано поточну версію пакета 0.8.40-1 замість 0.8.22 з методичних вказівок.
     Пакет встановлено командою sudo apt install ./mysql-apt-config_0.8.40-1_all.deb -y. Альтернативою є команда dpkg -i, проте вона потребує ручного встановлення залежностей пакета (їх перелік наведено в індексі репозиторію [8]), тоді як apt install із локального файлу розв’язує їх автоматично (див. рис. 4.8).

Створено базу даних командою CREATE DATABASE opencart CHARACTER SET utf8 COLLATE utf8_bin;: CHARACTER SET задає кодування символів, а COLLATE – правила порівняння рядків. Рисунок 4.16 – Встановлення Apache та перевірка його версії й стану
     Перед зміною конфігурації створено резервну копію. До директорії налаштувань перейдено командою pushd /etc/apache2/, а копію створено командою sudo cp /etc/apache2/apache2.conf /etc/apache2/apache2.conf.$(date -u +%Y%m%dT%H%M%SZ).bak. Ім’я копії містить мітку часу в UTC у форматі ISO 8601 (без двокрапок) та суфікс .bak. Наявність копії перевірено командою ls -l, прапорець -l якої дозволяє порівняти розміри файлів (див. рис. 4.17).

Рисунок 4.17 – Резервне копіювання конфігурації Apache
     Використання файлів .htaccess дозволено командою sudo sed -i 's/AllowOverride None/AllowOverride All/g' /etc/apache2/apache2.conf. Директива AllowOverride визначає, чи можуть файли .htaccess змінювати налаштування для каталогу. Згідно з документацією Apache, одним з випадків використання .htaccess є CMS, які постачаються разом із такими файлами [9]; це справедливо для OpenCart, проте наявність цього файлу в обраній версії документація не підтверджує. Команда замінює всі входження AllowOverride None у файлі, у тому числі у блоках <Directory> для /, /usr/share та /var/www/; точнішим було б обмежити заміну діапазоном рядків блоку /var/www/, проте в роботі виконано заміну згідно з методичними вказівками.
     Після цього повернуто до попередньої директорії командою popd, перезапущено службу командою sudo systemctl restart apache2 та перевірено стан: служба active (running) із 24.10.2026 19:55:09 UTC (див. рис. 4.18).

4.7 Встановлення PHP та PHP-FPM, з налаштуванням проксі HTTP-серверу Apache
     Актуальну версію PHP визначено через мета-пакет php: команда apt-cache depends php показала залежність php8.4, тобто в Debian 13 доступна PHP 8.4. Мета-пакет php8.4 при цьому не встановлювався: за його залежністю libapache2-mod-php8.4 | php8.4-fpm першим варіантом є модуль Apache, а потрібен PHP-FPM, тому встановлено конкретні пакети. PHP-FPM обрано замість mod_php, бо він відокремлює застосунок від веб-сервера: вони можуть перезапускатися незалежно, а також можуть застосовуватися політики безпеки для кожного застосунку окремо [3].
     Пакети підібрано за системними вимогами OpenCart [10]; відповідність вимог пакетам наведено в таблиці 4.2. Зокрема, вимога Curl означає саме розширення PHP php8.4-curl, а не системну утиліту curl. Наявність розширення Iconv перевірено командами apt-cache depends php8.4-fpm та apt-cache show php8.4-common | grep 'iconv': пакет php8.4-fpm залежить від php8.4-common, який надає php8.4-iconv (див. рис. 4.19). Для вимог OpenSSL Encrypt та Zlib окремих пакетів не встановлювалося; їхню відповідність підтверджено сторінкою попередньої перевірки інсталятора OpenCart. Рекомендовані налаштування PHP окремо не змінювалися.

5 ВІДПОВІДІ НА КОНТРОЛЬНІ ЗАПИТАННЯ
     1. Що таке стек LAMP і з яких основних компонентів він складається?
     LAMP – це класичний стек серверного веб-програмного забезпечення. Назва складається з перших літер його компонентів: Linux (операційна система), Apache (HTTP-сервер), MySQL або MariaDB (система управління базами даних) та PHP (мова програмування для обробки динамічного контенту).
     2. У чому полягає різниця між використанням PHP як модуля Apache (libapache2-mod-php) та режимом PHP-FPM?
     Модуль mod_php вбудовує інтерпретатор у процес Apache: php-файл інтерпретується безпосередньо, без передачі зовнішнім процесам. У режимі PHP-FPM Apache передає запит на .php окремому сервісу php-fpm за протоколом FastCGI (через модуль proxy_fcgi); php-fpm виконує файл та повертає результат серверу, який віддає його клієнту. Відокремлення застосунку від веб-сервера дозволяє перезапускати їх незалежно та застосовувати політики безпеки для кожного застосунку окремо [3].
     3. За що відповідає директива AllowOverride All у конфігураційному файлі Apache?
     Директива AllowOverride визначає, чи можуть файли .htaccess у каталозі змінювати налаштування сервера. Значення None повністю вимикає їх, а All дозволяє будь-які директиви з .htaccess. Це потрібно, коли CMS постачається разом із такими файлами [9]. Документація також радить уникати .htaccess, якщо є доступ до головного конфігураційного файлу, оскільки їх використання знижує швидкодію [9].
     4. Навіщо змінювати права власності каталогу CMS на користувача www-data?
     Користувач www-data – це обліковий запис, від імені якого в Debian за замовчуванням працюють процеси веб-сервера та PHP. Щоб CMS могла читати свої файли та записувати дані (наприклад, конфігурацію під час встановлення), власником каталогу має бути саме цей користувач. Права 755 дозволяють решті користувачів лише читання та виконання.
     5. Чому важливо видаляти каталог install/ після завершення інсталяції CMS?
     Каталог містить майстер встановлення. Якщо залишити його, будь-хто, хто має доступ до сайту, може повторно запустити інсталятор, змінити конфігурацію підключення до бази даних або перезаписати дані. Тому після завершення встановлення цей каталог видаляють.
     6. Які SQL-команди використовуються для створення користувача та надання йому повних прав на конкретну БД?
     Для цього використовуються команди CREATE USER 'ім’я'@'хост' IDENTIFIED BY 'пароль'; та GRANT ALL PRIVILEGES ON база.* TO 'ім’я'@'хост';. У цій роботі: CREATE USER 'devops-user'@'localhost' IDENTIFIED BY 'devops-user'; та GRANT ALL PRIVILEGES ON opencart.* TO 'devops-user'@'localhost';, а також аналогічні команди для хоста %.
6 ВИСНОВКИ
     У результаті виконання лабораторної роботи:
* розгорнуто стек LAMP у Debian 13 (trixie) у середовищі WSL: Apache, MySQL (серія 9.7 LTS) та PHP 8.4 із PHP-FPM, а також CMS OpenCart 4.1.0.4;
* отримано навички встановлення програмного забезпечення з додаткового APT-репозиторію (MySQL) та вибору серії LTS або Innovation;
* налаштовано СУБД: виконано безпечне налаштування, створено базу даних та користувача з мінімально необхідними правами;
* розглянуто способи взаємодії веб-сервера з PHP (CGI, FastCGI та PHP-FPM, mod_php) та налаштовано Apache на роботу з PHP-FPM через proxy_fcgi;
* виконано веб-інсталяцію OpenCart та видалено каталог встановлення.
     Версії програмного забезпечення в методичних вказівках (Debian 10, PHP 7.3, OpenCart 3.0.3.8) застаріли, тому їх замінено актуальними. Це показало, що суть роботи полягає не в конкретних версіях, а в принципах: підключення сторонніх репозиторіїв, взаємодія веб-сервера з інтерпретатором, налаштування СУБД та прав доступу.
